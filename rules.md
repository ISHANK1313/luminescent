# Rules — Coding & Behaviour Standards for Vera Bot

**Status**: Draft v1.0 (pre-implementation)
**Last updated**: 2026-08-30
**Audience**: Developer, LLM agents, reviewer

All code must obey these rules. The judge harness will enforce some (via API contract), but the full set is here for the participant and any downstream agents.

---

## 1. Determinism Rules (CRITICAL)

| # | Rule | Rationale | Check |
|---|---|---|---|
| R1 | **No RNG in composition** — never call `random.*`, `uuid.uuid4()`, `time.time()` (except in `now` field from judge tick payload), or any non-deterministic source inside `compose()`. | Judge simulates determinism; same contexts → byte-identical `body` must hold. `now` is injected from judge tick, not generated by bot. | `body` output repeated across 2 calls with identical inputs? ✅ |
| R2 | **All composition steps are pure functions of their inputs** — `trigger_router(kind)`, `signal_selector(payload)`, `slot_extractor(contexts)`, `voice_renderer(taboos)`, `cta_policy(...)` have no hidden state. | Enables scoring across 30 canonical test pairs and post-submission context injection. | Unit test: each sub-function returns identical output for identical input. ✅ |
| R3 | **In-memory store is versioned per `(scope, context_id)`** — re-post same/lower version = no-op; higher version replaces atomically. Do NOT clear/store outside these keys. | Idempotent per testing brief §2.1; 409 on stale version; prevents lost updates. | `context_store.get("merchant", "m_001")` returns latest version after re-post. ✅ |
| R4 | **No external data fetching during tick/reply** — bot must not call any non-LLM external API with merchant/customer payload inside < 30s. | Privacy rule §11 of testing brief; rate limits. Optional LLM polish only via pre-approved API with strict token budget. | `/v1/tick` response < 30s wall clock; no outbound HTTP with payload data. ✅ |
| R5 | **Do not iterate dict keys in definition order that varies across runs** — if dict ordering matters, sort keys before use (e.g., `sorted(merchant["offers"], key=lambda o: o["id"])`). | Python 3.7+ guarantees insertion order, but explicit sort avoids subtle diffs when dicts constructed from different JSON sources. | Slot extraction uses sorted iteration. ✅ |

## 2. Message Quality Rules

| # | Rule | Detail | Penalty if violated |
|---|---|---|---|
| R6 | **Single primary CTA** — exactly one of: binary YES/STOP, open-ended ask, or none (info-only). Detect and flag if message body contains >1 CTA pattern (`reply YES for X, NO for Y`). | Scoring dimension "Engagement compulsion"; multiple CTAs confuse merchant. | −2 per occurrence (judge). |
| R7 | **No fabrication** — every number, price, date, offer, source citation, competitor name must exist in the pushed contexts (category/merchant/trigger/customer). If not in context → omit or use "unknown" phrasing. | Top judge penalty −2; hallucination is a #1 anti-pattern. | −2 per fabricated fact; possible fail if severe. |
| R8 | **Specificity-first** — anchor on at least one verifiable fact per message (number, date, headline, peer stat). Generic "increase your sales" → penalized. | Scoring dimension "Specificity". | Score ≤ 4 on Specificity if no anchor. |
| R9 | **Voice match** — enforce category voice/tone/vocab rules from `category` context. For dentists: clinical peer terms OK, taboos `["cure", "guaranteed"]`; salons: warm/friendly; restaurants: operator-to-operator; gyms: coaching/motivational; pharmacies: trustworthy/precise. | Scoring dimension "Category fit". | score ≤ 4 on Category fit if voice breached. |
| R10 | **Language match** — honor `merchant.identity.languages` (or customer identity if customer-facing). Hindi-English code-mix where `languages` includes `hi`; pure English OK as default. | Scoring dimension "Merchant fit". | score ≤ 4 on Merchant fit if language ignored. |
| R11 | **Anti-repetition** — never send a `body` sent before in the same conversation (`conversation_id`). Also avoid sending the exact same body to the same merchant within 7 days globally (hash of body + merchant_id). | Scoring penalty −2 per repeat; merchant annoyance. | −2 per repeat occurrence; judge detects via transcript. |
| R12 | **CTA placement** — the CTA (or “no CTA”) must land in the last sentence of the body. No buried CTAs after long preambles. | Scoring dimension "Engagement compulsion"; readability. | −1 if CTA not in last sentence. |
| R13 | **No long preambles** — first 2 sentences should contain the hook + reason-why-now. The CTA or the core fact should appear by sentence 3. | Readability + merchant engagement. | Judge deducts if preamble > 2 sentences before point. |
| R14 | **Single binary commitment** — Reply YES/STOP, not multi-choice ("Reply YES for X, NO for Y, MAYBE for Z"). For slot offers, prefer “Reply 1 for X, 2 for Y” format or open-ended “tell us a time that works.” | Scoring + usability. | −2 if truly multi-choice. |
| R15 | **Suppression key respected** — never emit an action whose `suppression_key` already expired or was already fired for this merchant in this session. | Dedup per trigger design. | −1 if sent after expiry. |

## 3. Endpoint Contract Rules

| # | Rule | Detail |
|---|---|---|
| R16 | **`/v1/healthz`** — return 200 `{status: "ok", uptime_seconds, contexts_loaded: {category, merchant, customer, trigger counts}}`. Must complete in < 5s (judge timeout) or < 60s judge polls every 60s; 3 consecutive failures → disqualified for that test slot. |
| R17 | **`/v1/metadata`** — return 200 with `{team_name, team_members[], model, approach, contact_email, version, submitted_at}`. |
| R18 | **`/v1/context`** — idempotent on `(scope, context_id, version)`: re-post same version → `{accepted: true, ack_id, stored_at}` (no-op for same version; higher replaces). Lower version → `{accepted: false, reason: "stale_version", current_version}`. 400 on malformed: `{accepted: false, reason: "invalid_scope"/..., details}`. Payload ≤ 500 KB. |
| R19 | **`/v1/tick`** — body `{now, available_triggers[]}`. Returns `{actions: [...]}` where each action has all fields documented in testing brief §2.2. Max 20 actions per tick. Must complete < 15s (simulator) / < 30s (judge). Empty `actions: []` is valid and preferred over spam. |
| R20 | **`/v1/reply`** — body `{conversation_id, merchant_id, customer_id, from_role, message, received_at, turn_number}`. Response exactly one of: `{action: "send", body, cta, rationale}`, `{action: "wait", wait_seconds, rationale}`, `{action: "end", rationale}`. Must complete < 15s / < 30s. After 30s → judge marks timeout, proceeds. |
| R21 | **`/v1/teardown`** (optional per brief §11) — wipe all in-memory state. Return 200 `{wiped: true}`. |

## 4. Error-Handling Rules

| # | Rule | Detail |
|---|---|---|
| R22 | **Malformed JSON** — if request body can't be parsed → return 400 with error info (per testing brief). Bot must not crash on bad input. |
| R23 | **Timeouts** — if compose or any internal step exceeds 15s (simulator) / 30s (judge) → return empty `actions: []` from tick; return `{action: "wait", wait_seconds: 0, rationale: "compose timeout — back off"}` from reply. Never hang indefinitely. |
| R24 | **Unknown trigger kind** — if `trigger.kind` not in registered strategy table → default to graceful-degradation: compose a generic-but-grounded nudge from available data; if insufficient data → emit no action (`actions: []`). Log a warning. |
| R25 | **Missing context** — if compose is called with `None` for any required context → return empty `actions: []` from tick; from reply, return `{action: "end", rationale: "missing context for conversation"}` (graceful exit). |
| R26 | **Response schema validation** — every response JSON must match the documented shape. Extra fields are permitted (judge ignores unknown), missing required fields → judge scores 0 for that dimension. |

## 5. Logging & Privacy Rules

| # | Rule | Detail |
|---|---|---|
| R27 | **Log what you send** — every `/v1/tick` and `/v1/reply` action must have a corresponding log entry with: timestamp, endpoint, request body (scrubbed of PII), response body (first 200 chars only), duration_ms. Do NOT log full merchant/customer payloads unless redacted. |
| R28 | **Never log raw PII** — phone numbers, exact addresses, emails beyond what's in the context are redacted in any logs. If you must log for debugging, mask: `xxx-xxx-1234` pattern. |
| R29 | **No external transmission of context data** — do not POST/GET merchant/customer/context data to any external API except the optional LLM polish guard (see R4, R23). The test environment is the only destination. |
| R30 | **`/v1/teardown` wipes state** — on receiving it, clear all in-memory dicts (`ctx.ctx.clear()`). Do not persist beyond test window. |

| # | Rule | Detail |
|---|---|---|
| R31 | **Unit tests** — each sub-function (`trigger_router`, `signal_selector`, `slot_extractor`, `voice_renderer`, `cta_policy`) has a pure-Python unit test file (`tests/test_*.py`) covering at least 5 representative inputs per function. |

First scored run: 35.05/50 PASS. |

## 7. Anti-Patterns the Judge Will Penalize (summarized from brief §11 + §8)

- Generic offers ("Flat 30% off") when service+price available ("Haircut @ ₹99")
- Multiple CTAs in one message
- Buried call-to-action (the "what to do" should land in the last sentence)
- Promotional tone for categories that need clinical/peer voice (dentists, doctors, lawyers)
- Hallucinated data (citing research not in context, naming competitors not in context)
- Long preambles ("I hope you're doing well. I'm reaching out today to…")
- Re-introducing yourself after the first message
- Ignoring the language preference ("hi-en mix" merchant getting pure English)
- Sending the same message verbatim that was sent before (anti-repetition −2)
- Auto-reply pollution (failing to detect + exit gracefully)
- Qualifying after explicit intent ("ok let's do it") — lost momentum
